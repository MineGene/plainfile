# Plainfile

See — and soon remove — the hidden information in your files on macOS: where a photo was taken, which device made it, who wrote a document, and the web page you downloaded it from.

Plainfile is free, open source (MIT) and private by design. It has **no network access at all**: macOS's sandbox blocks every connection, so nothing about your files can leave your Mac.

> **Built with AI.** Plainfile's code is written by Claude, Anthropic's AI model, working through Claude Code, and checked by layered automated tests and the maintainer. See [How Plainfile is made](#how-plainfile-is-made).

> **Status: early preview (0.1).** This version only *shows* metadata. Nothing is changed. Removing metadata, previewing the result and undo are being built next.

## What it shows today

| Where | What |
| --- | --- |
| Photos (JPEG, HEIC, PNG, TIFF, GIF, WebP and other formats macOS can read) | GPS location, camera make, model and serial numbers, maker notes, dates, author and copyright, editing software, XMP data |
| Any file | Download source (the web address macOS records when you download something), Gatekeeper download flag, Finder tags and comments, file dates, file name |

Items are grouped in plain language (Location, People and authorship, Device, Downloaded from, …) and marked with how much they reveal.

## Install

1. Download the latest `Plainfile-x.y.z.dmg` from [Releases](https://github.com/MineGene/plainfile/releases), open it and drag Plainfile to Applications.
2. Open Plainfile. macOS will say it can't verify the developer. That's expected: Plainfile is free and isn't notarised by Apple.
3. Open **System Settings › Privacy & Security**, scroll down and click **Open Anyway**, then confirm. You only need to do this once per version.

Only download Plainfile from the Releases page above.

**Verify it yourself (optional).** You don't need to trust this page, the maintainer, or the AI that wrote the code. Every release is built by GitHub from this public source, with a signed build record logged publicly by Sigstore, and builds are reproducible. One script checks it all:

```sh
git clone https://github.com/MineGene/plainfile.git && cd plainfile
scripts/verify-release.sh 0.1.1            # checksum, signed build record, app contents, permissions
scripts/verify-release.sh 0.1.1 --rebuild  # also rebuild from source and compare (needs the Xcode in .xcode-version)
```

It confirms the DMG matches its checksum, that GitHub's signed record says this repository's release workflow built it, that the app inside matches that record file by file, and that the app has no network access. With `--rebuild` it builds the same source itself and checks you get exactly the same app.

Requires macOS 15 or later on a Mac with Apple silicon (M1 or later). Intel Macs are not supported.

**Updates:** Plainfile never checks for updates, because it can't go online. Click **Watch › Custom › Releases** on this page to be told about new versions.

## Privacy and security

- **No network access.** The app has no network entitlement, so macOS refuses any connection it might try to make. Every build checks this automatically.
- **No telemetry, analytics, crash reporters or third-party SDKs.**
- **Untrusted files are read in a separate, locked-down process** with no access to your files or the network. If a malicious file ever exploited a bug in the reader, it would be stuck there.
- **Nothing is saved.** What Plainfile finds stays in memory and disappears when you quit.
- **Honest results.** "No metadata found" is never a guarantee. Watermarks, hidden data in pixels and what's visible in a photo can't be removed by any metadata tool.

Found a security problem? Please report it privately — see [SECURITY.md](SECURITY.md).

## How Plainfile is made

Plainfile is an experiment in building a security-sensitive app with an AI doing the programming, done in the open.

- **Who writes the code:** Claude (Anthropic's AI model), working through [Claude Code](https://claude.com/claude-code). Design decisions, priorities and real-world testing come from the maintainer.
- **How changes land:** every change is a pull request. It merges automatically only after all required checks pass. Releases are started and approved by the maintainer.
- **How you can tell:** commits made with Claude carry a `Co-Authored-By: Claude` line, and its pull requests say "Generated by Claude Code".
- **Why the testing is layered:** an AI can make the same mistake in the code and in the tests that check it. So results are checked several independent ways: a fresh re-scan, a search of the cleaned file's raw bytes, a pixel-by-pixel picture comparison, and (planned) cross-checks with long-established tools such as ExifTool and mat2, real-world sample files, and tests that deliberately break the cleaner to prove the tests notice. The full plan is in [CONTRIBUTING.md](CONTRIBUTING.md#testing).
- **What stays the same:** the safety design doesn't depend on the code being perfect. The app has no network access at all, and files are read in an isolated process that can't open other files.

Every commit since `9ada525` carries the attribution itself. Six earlier commits on `main` were also written with Claude but lost the attribution during an early clean-up, and are listed here instead of rewriting history (which would break the link between releases and their source): `3a5ae97`, `00c21d8`, `4b5f320`, `914a697` (#4), `6f28c33` (#5) and `f7fb1ed` (#6). Only `c6e4b52`, the initial commit, was made without Claude.

## How it's built

Native Swift and SwiftUI, using Apple's own frameworks (ImageIO, and soon AVFoundation and PDFKit) instead of third-party parsers.

- `Plainfile/` — the app (SwiftUI window, file handling)
- `PlainfileParser/` — the isolated parser service (XPC)
- `Packages/PlainfileCore/` — scanners and models shared by both, with tests
- `Config/` — entitlements (sandbox permissions) for the app and the parser
- `Plainfile.xcodeproj` — the Xcode project; new Swift files in `Plainfile/` or `PlainfileParser/` are picked up automatically

Everything is built, tested and released by GitHub Actions — no developer hardware involved:

- **CI** (every push, every pull request and weekly): core tests, app build, and a check that the app is sandboxed, has no network entitlement, and the parser has no file access.
- **Commit privacy** check: every commit must use a GitHub no-reply email, with no attribution trailers.
- **CodeQL** security analysis of the Swift code, and **zizmor** audits of the workflows themselves.
- **Minimal dependencies:** the app contains no third-party code, and it's built with Apple's tools only. Every GitHub Action is pinned to an exact commit; Dependabot proposes updates after a 7-day cooldown.
- **Release** (started with one tap from the Actions tab, after approval): builds, ad-hoc signs, packages a DMG, attaches a checksum and build attestation, and publishes the release.

To build locally on an Apple-silicon Mac with Xcode: `scripts/build-app.sh`.
